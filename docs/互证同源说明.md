# 互证同源说明（当日锁定）

> **锁定日期：2026-11-21（当日锁死）。** 路径钉死为**路径甲**，互证与正式册同源可修。
> 本说明与 `backend/formal_source.py` 同为契约；改动须先改说明与红测，不得只改文案。

## 根因

互证页（`/api/proof/{party_key}`）直接 `SELECT * FROM bookings` 拼装；正式册
（`/api/bookings`）走 `JOIN slots`；对账（`/api/reconcile`）只按
`status='已确认'` 求和。三处口径不一，于是出现「互证有行、正式册查无、对账仍打勾」的假绿。

## 唯一定义（路径甲）

`backend/formal_source.py` 是五处唯一的同源派生点：

- **路径甲**：互证只读已确认正式行，与盘面占用在同一事务内派生，**不得另造缓存**。
- 正式行 = `status='已确认'` **且** 档期存在（JOIN 命中）**且** `snapshot_gen = slots.generation`。
- 其余已确认行归为**歧义行**（无主档期 / 快照代落后），五处同态暴露，不得静默吞掉。
- **失败则查询零写**：互证、对账、档期盘、审计、对账查询全部纯读，异常不落任何写。
- 路径乙（分裂时落影子修复单再晋升）**未启用**；甲、乙两边**不得混用**。

## 偏航与拒写

写侧（确认入册）在落正式行前检查同源报告；若已存在分裂：

1. 记审计动作 **`互证同源偏航`**（含当事人、正式/歧义/无主计数）；
2. 以 409 **拒写**，正式册、盘面占用、占位状态**零改**；
3. **禁止只改互证文案**来掩盖分裂。

## 争用

两人同时修同一当事人，须先抢档锁（`slot:{code}`）与当事人锁（`party:{party_key}`）；
后到者只留争用痕（`contention_log`，动作 `争用`），业务零写。

## 五处同态

以下五处全部取自 `formal_source`，口径必须一致：

1. 互证页 `/api/proof/{party_key}`
2. 正式册 `/api/bookings`
3. 档期盘 `/api/slots`、`/api/slots/{code}`、`/api/dashboard`
4. 对账 `/api/reconcile`、`/api/reconcile/{code}`
5. 审计 `/api/audit`

修完人数必须对得上：正式册行数 = 档期盘正式册计数 = 对账正式席合计。
